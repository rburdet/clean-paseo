# clean-paseo: Bulk Archive Workspaces Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A client-only Paseo plugin that lists every active workspace sorted by activity, lets the user multi-select, and archives the selection in one go.

**Architecture:** Pure logic (row mapping, sorting, relative time, sequential archive runner, paginated fetch) lives in `shared/` and is unit-tested with Node's test runner against fakes. One React Native screen in `client/` wires that logic to `usePaseo().workspaces`, registered with `addScreen` + `addSidebarHeaderItem`. No server code, no RPC.

**Tech Stack:** TypeScript, React 19 / React Native 0.81 (via Paseo host), `@getpaseo/plugin@0.15.0`, `@tanstack/react-query`, `node --experimental-strip-types --test`.

**Spec:** `docs/superpowers/specs/2026-11-15-bulk-archive-workspaces-design.md`

## Global Constraints

- Plugin id `clean-paseo`; manifest `requirements.paseo: ">=0.15.0"` (as generated by `paseo plugin init`).
- Only public API: `usePaseo().workspaces.list(...)`, `usePaseo().workspaces.archive(id)`, `client.addScreen`, `client.addSidebarHeaderItem`, `@getpaseo/plugin/client/ui` components.
- Archive is the official Paseo archive; never touch files directly.
- Archive in sequence (one at a time), never in parallel; one failure must not stop the rest.
- Nothing is archived without an explicit in-screen confirmation step.
- Workspaces with `activityAt === null` sort as the oldest.
- UI copy is Spanish: sidebar/screen title `Limpiar workspaces`; button `Archivar N`; confirm text `¿Archivar N workspaces?`; null activity `sin actividad`.
- Node ≥ 24 (installed: v24.18.0). The directory is not a git repo yet; Task 1 runs `git init`.

## Review Focus

1. **More workspaces than one page** — `list()` paginates; the screen must show all of them, not only the first page. → test in Task 3.
2. **Workspace archived elsewhere while selected** (or already `archivingAt`) — archive call rejects; the runner records it as failed and continues; list refresh drops it. → test in Task 2 (rejecting fake mid-list).
3. **Selection outliving the list** — after refresh, ids no longer present must be dropped from the selection so `Archivar N` never counts ghosts. → test in Task 1 (`pruneSelection`).
4. **Invalid / future `activityAt`** strings — must not crash or sort as newest-NaN; treat unparsable as null. → test in Task 1.
5. **Pressing Archivar twice / during a run** — button disabled while running; runner is never started twice. → manual check in Task 4.

  export type WorkspaceStatus = "running" | "attention" | "needs_input" | "failed" | "done";
  export interface WorkspaceInput {          // structural subset of PaseoWorkspace
    id: string; name: string; title?: string | null; projectDisplayName: string;

  - `pruneSelection` keeps only ids present in rows and not `archiving`.

### Task 2: Sequential archive runner

**Files:**
- Create: `shared/bulk-archive.ts`
- Test: `test/bulk-archive.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export interface ArchiveProgress { done: number; total: number; currentId: string | null }
  export interface ArchiveOutcome { archived: string[]; failed: { id: string; error: string }[] }
  export async function archiveSequentially(
    ids: string[],
    archive: (id: string) => Promise<unknown>,
    onProgress?: (p: ArchiveProgress) => void,
  ): Promise<ArchiveOutcome>;
  ```
  - Calls `archive` one id at a time in the given order, awaiting each. Errors are caught; `error` = `err instanceof Error ? err.message : String(err)`. Calls `onProgress` before each call (`currentId` = that id, `done` = count finished) and once at the end (`currentId: null`, `done === total`).

  - `continues after a failure` — fake rejects for `b` with `new Error("gone")` → archived [a,c], failed `[{id:"b", error:"gone"}]`.
  - `reports progress` — last progress event is `{done:3,total:3,currentId:null}`; first is `{done:0,total:3,currentId:"a"}`.
  - `empty list` → `{archived:[],failed:[]}`, `archive` never called.

### Task 3: Fetch all workspaces

**Files:**
- Create: `shared/fetch-all.ts`
- Test: `test/fetch-all.test.ts`

**Interfaces:**
- Consumes: `WorkspaceInput` from Task 1.
- Produces:
  ```ts
  export interface ListPage<T> { entries: T[]; pageInfo: { nextCursor: string | null; hasMore: boolean } }
  export type ListFn<T> = (opts: {
    sort: { key: "activity_at"; direction: "asc" }[];
    page: { limit: number; cursor?: string };
  }) => Promise<ListPage<T>>;
  export async function fetchAllWorkspaces<T>(list: ListFn<T>, pageSize?: number): Promise<T[]>; // default 100
  ```
  - Loops while `hasMore && nextCursor`, passing `cursor`; concatenates entries. Hard stop after 50 pages (guard against a cursor loop) — returns what it has.
  - The screen passes `(o) => paseo.workspaces.list(o)`; it's structurally compatible with `PaseoWorkspaceListOptions`. Do not pass `includeBackground` (background workspaces stay hidden, like the CLI's `workspace ls`).
